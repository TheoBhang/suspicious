## What is already solid

- Knox token lives in an `httpOnly`, `SameSite=Strict` cookie, not `localStorage`
  (`api/authentication.py`, `api/views/auth.py`).
- OIDC flow uses state + nonce + PKCE S256 and JWKS signature validation;
  the unverified fallback is refused when `DEBUG` is off (`api/views/oidc.py`).
- Login throttled (`5/min`); default DRF permission is `IsAuthenticated`.
- Production boot guard rejects `ALLOWED_HOSTS=*`; HSTS / secure cookies on.
- Upload zip-bomb guard (entry count, total size, ratio) in `api/serializers/submit.py`.
- `torch.load(..., weights_only=True)` in the AI analyzer.
- urlscan screenshot fetch is host-pinned, size-capped and PNG-magic-checked.
- LDAP TLS verification defaults to `DEMAND`; opt-out logs a warning.
- Mail preview renders text, not raw HTML; no `dangerouslySetInnerHTML` in `src/`.
- CSP set at the Traefik layer (`traefik/dynamic/tls.yaml`).

## Findings

### Security

**SEC-1 — Case challenge consumes its token on `GET`.**
`api/views/challenge.py` (`CaseChallengeTokenView.get`) marks the token used and
runs `run_case_challenge` on a plain GET, with `AllowAny`. The link is sent by
email. Mail-security link scanners (Defender Safe Links, Proofpoint URL
Defense, Mimecast) pre-fetch links, so a challenge can fire without the
reporter clicking — and the real click then gets "Invalid or expired token".
Fix: GET renders a confirmation page; POST consumes the token.

**SEC-2 — OIDC account linking trusts unverified email.**
`_get_or_create_user` resolves users by `email` only and never checks the
`email_verified` claim. On an IdP that allows self-asserted emails, a user can
log in as any existing local account with that address (including Admin/CERT).
Also: `User.email` is not unique, so duplicates raise `MultipleObjectsReturned`;
a `preferred_username` already taken by another account raises `IntegrityError`.
Both surface only as a generic `user_resolution_failed`.

**SEC-3 — OIDC accepted algorithms come from the IdP.**
`_validate_id_token_pyjwt` passes `id_token_signing_alg_values_supported` from
discovery straight to `jwt.decode`. Pin an allowlist (RS256/PS256/ES256), reject
`none`/`HS*`. `PyJWKClient` is also rebuilt per login (no JWKS cache).

**SEC-4 — Cookie auth has no CSRF check.**
`KnoxCookieAuthentication` authenticates from a cookie but, unlike DRF's
`SessionAuthentication`, never calls `enforce_csrf`. Protection rests entirely
on `SameSite=Strict`, which does not cover same-site attackers (sibling
subdomains, a compromised internal app on the same registrable domain).
Add an Origin/`X-CSRFToken` check for unsafe methods on cookie-authenticated
requests.

**SEC-5 — Cortex webhook auth is a static bearer, not an HMAC.**
`api/views/cortex_webhook.py` compares `Authorization: Bearer <secret>` with
`compare_digest`. Docs (`CLAUDE.md`, architecture) describe it as
"HMAC-signed". No body integrity, no timestamp/replay window. The dedup key is
also written *before* enqueue, so a failed enqueue drops the job to the
5-minute cron fallback. Either implement body HMAC + timestamp, or correct the
docs and accept the bearer model explicitly.

**SEC-6 — Container images: unpinned bases, root users.**
`suspicious-ui/Dockerfile` uses floating `node:alpine` / `nginx:alpine` and runs
as root; `Analyzers/AIMailAnalyzer/Dockerfile`, `Analyzers/MailHeaderAnalyzer/Dockerfile`
have no `USER`. Pin versions (Dependabot already tracks docker), use
`nginxinc/nginx-unprivileged`, add non-root users to analyzers.

**SEC-7 — Secret scanning disabled.**
The gitleaks job in `.github/workflows/security.yml` is commented out (license
requirement). Replace with the gitleaks binary (no license needed) or
TruffleHog OSS.

### Correctness / reliability

**REL-1 — Mail-road `mail_band_escalation` blocked on a design decision.**
From `docs/plans/2026-09-03-ioc-road-followups.md` §8: `process_mail` still feeds
embedded IOC artifacts into `score_case`, so wiring escalation double-counts.
Needs the Option-B split and a `backtest_scoring --road mail` sign-off.

**REL-2 — Broad exception handling.** ~308 `except Exception` sites in
non-test backend code. Many are intentional best-effort paths, but on the
scoring/finalise path they can turn bugs into silent "Inconclusive" verdicts.
Audit the finalise, scoring and connector-dispatch paths first; narrow or
re-raise, and count swallowed errors in a metric.

**REL-3 — Legacy `nonFileIocs` still live.** IOC-road spec §11 defers
backfill + removal; investigations filters still branch on it.

### Maintainability

**MNT-1 — RBAC group names hard-coded.** `"CERT"`, `"CISO"`, `"Admin"` literals
appear in 9 modules (api permissions, views, `tasp/services/challenge.py`,
`profiles/`, `settings.py`). One constants module + one `is_investigator`
helper.

**MNT-2 — Oversized modules.** `email-feeder/classes/services/mailbox_service.py`
(1066 LOC), `cortex_job/cortex_utils/cortex_and_job_management.py` (939),
`suspicious-ui/src/pages/InvestigationPage.tsx` (1422),
`SubmissionsPage.tsx` (1126), `styles/themes.ts` (4884 — mostly data).

**MNT-3 — Python version drift.** Backend 3.12.13; feeder, AIMailAnalyzer and
MailHeaderAnalyzer on 3.14; AIMailAnalyzer training image on 3.12.

**MNT-4 — Dependabot gaps.** `Analyzers/MailHeaderAnalyzer` (pip + docker) and
`Suspicious/requirements-connectors.txt` are not covered.

### Testing / CI

**TST-1 — Playwright specs not in CI.** `suspicious-ui/e2e/*.spec.ts` (4 specs)
never run; CI runs Vitest only, and `e2e-deploy` is a backend smoke.

**TST-2 — No coverage measurement.** Neither backend nor frontend reports
coverage; no floor to stop regressions.

**TST-3 — Frontend page coverage thin.** 53 test files for 171 source files;
the largest pages (Investigation, Submissions, Profile, Login) carry most logic.

### Docs

**DOC-1 — Drift.** `CLAUDE.md` says the webhook is HMAC-signed (see SEC-5) and
quotes "525 tests" (suite is ~856+). The LDAP TLS warning in
`suspicious/settings.py` names `integrations.ldap.verify_ssl`, but the setting
lives under `authentication.ldap`.
